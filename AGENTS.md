# marktplatz

See README.md for what this is and how skills flow from `quarantine/` to `approved/`.

- Keep it simple: no fallbacks, no overrides, no optional manifest fields.
- Everything about a skill stays in `approved/<id>/<version>/`. There are no central lockfiles.
- Skill versions reach the market only through `.github/workflows/quarantine.yml`: daily it moves `quarantine/*.yaml` to newer upstream releases, checks every unchecked version in its own job, and opens one PR (`bot/admit`, as a GitHub App) that a person merges with the bumps and the `approved/` or `gate/` records; merged requests take the same path. Site PRs get a Cloudflare Worker Preview (`preview.yml`); merges to main deploy (`deploy.yml`).
- Never edit files under `approved/` or `gate/` by hand; they are produced by `scripts/promote.ts` and checked by `scripts/verify.ts`.
- A skill that does not clear the scan is held at the gate: `gate/<id>/<version>/` keeps only its provenance (with the SKILL.md description) and scan results, never its files. Every checked version keeps `scan/summary.json` (what the site reads) and each scanner's raw report (`scan/<scanner>.json`), and the site links to both. Guilds may list held skills; they are offered only when someone ticks "Also offer the ones at the gate" in the shop (`/with-held` in the URL), and then install straight from their own repository at the checked commit, marked "not cleared" with the blocking rules in every marketplace entry, in `/llms.txt`, `/catalog.json` and the review prompt. The UI never blames: it says "at the gate" and "not cleared", never "rejected".
- Use bun for everything (`bun test`, `bun scripts/...`, `bun run build`).
- `src/lib/emitters.ts`, `src/lib/types.ts`, `src/lib/browse.ts` and `src/lib/watch.ts` run in the browser; don't import node or bun modules there.
- Every harness reads its own flavour of marketplace file, so `src/lib/emitters.ts` has one emitter per harness, and there is no shared or hosted marketplace file. Claude Code gets each guild as one plugin (`<role>-guild`, `strict: false`, listing its skills' folders under `approved/`) and each skill as a plugin of its own; Codex gets one plugin per skill in its own format. Every source is pinned to the build commit. The install commands move the file into `~/.marktplatz/<harness>/` before adding it, because both harnesses read a local marketplace where it was added. `InstallPanel` has a tab per harness, plus a prompt that asks your agent to review the skills first.
- Pages: the shop (`/`, also `/market/*` and `/?add=skill:<id>|guild:<id>`), skill pages (`/skills/<id>`: the rendered SKILL.md via `src/lib/markdown.ts`, which escapes raw HTML, keeps only safe links, turns images into links and moves headings down two levels; files with scripts flagged; context cost; the watch's verdict; provenance), guild pages (`/roles/<id>`), the Guilds and Skills indexes (`/roles`, `/skills`), `/ledger` (every verdict, and the findings of skills at the gate), `/watch` (how admission works, the watchmen from `src/lib/watch.ts`, which must stay in step with `src/lib/scan.ts`, and what they cannot promise), `/request` (a form that opens a quarantine request on GitHub), and `/licenses` (charters). Every page opens with `<PageHead>` (`src/components/PageHead.astro`): eyebrow and title, a lede that says what the page is for and how to use it, then badges and actions; skill and guild pages add their icon. Every page but the shop passes `crumbs` to `Layout.astro`, which renders a sticky breadcrumb on one line (the page's own name shortens with an ellipsis). Pages also carry `<Outline />` (last in a side column, or in `.with-outline`'s own column): an always-present "On this page" outline built from the headings in `<main>` (h2 sections, h3 subheadings, the recipe's h4s), docked while scrolling, the current part marked; below 1024px the breadcrumb's last step becomes a menu of the same sections, as in Starlight. For machines: `/catalog.json`, `/llms.txt`, README badges at `/badges/<id>.svg`.
- Design system: every value lives in `src/styles/tokens.css` (colours as semantic tokens, a type scale, a 4px space scale, radii, motion); `src/styles/components.css` holds the primitives (panel, name tag, buttons, badges, chips, tabs and segments, search, fields, tables, code blocks, disclosures, rows, notes); area files (`layout.css`, `shop.css`, `skill.css`, `watch.css`, `scene.css`) only arrange primitives. No hard-coded colours, sizes or gaps outside `tokens.css`, and no Tailwind utilities in markup. Two surfaces: the page (`--ink-*`, parchment by day, night blue by night) and slate panels (`--panel-*`, the same in both themes). Fonts come from Astro's Fonts API (`fonts` in `astro.config.mjs`, `<Font />` in `Layout.astro`): Pixelify Sans for what you scan (titles, labels, buttons, tabs, tags), IBM Plex Sans for what you read, IBM Plex Mono for commands and code. Every viewport gets the whole site: below 1024px the nav takes its own row and on phones it wraps rather than scrolling out of sight, gaps between sections tighten on phones, and wide tables turn into stacked cards there. Interaction: selected is the blue bar, one gold primary action per panel, status is always a badge (ok cleared, danger not cleared, warn take care), long secondary content folds into a disclosure, copy sits in a code block's head. One word per concept in the UI: skill (never "ware"; the stalls in the painting sell wares, the site offers skills), guild, charter, crafter, watchmen, cleared / not cleared, at the gate, notes (did not block) and findings (blocked).
- Licenses: a skill needs an SPDX license (GitHub's `spdx_id`), or one of `KNOWN_LICENSES` in `src/lib/license.ts`, which are source-available licenses recognised by the sha256 of their exact text and shown with their terms on /licenses. The repo's `LICENSE` and `NOTICE` are copied next to the skill.
- No install counts, rankings or paid placement: guilds are curated by hand, and every claim on the site links to the evidence.
- The site is a pixel-art market town in the manner of Sea of Stars: a steep top-down view (the ground fills the frame, walls face the camera, roofs are seen from above), textures from the game (sand with a grain lattice, leafy grass with ragged edges, bevelled flagstones, cliffs of stacked stone columns, canopies built leaf by leaf), dark selective outlines on every object, one sun up and to the right (shadows fall down-left), smooth modern light on top of crisp pixels, and JRPG-style UI (slate panels, gold name tags, a blue selection bar with a gloved pointer, and the wizard's portrait, which `portrait()` in `market.ts` cuts from the painting itself so he always looks the same as at his stall).
- The shop is built for hundreds of skills and dozens of guilds: search first (`/` focuses it; every word must match), tabs for guilds and skills with live counts, a few filters (guild, license, author) whose options show how many results they'd give, applied filters as removable chips, bulk add/remove for what is shown, and dense rows that go in or out of the scroll with one click, rendered in pages as you scroll. The search and filter logic is in `src/lib/browse.ts` (browser-safe, tested). The scroll panel (sticky beside the list, or one tap away on phones) always shows the harness, what's inside, the download and the install commands. The selection lives in the URL path.
- The hero spans the full width at every size: `Scene.astro` puts the 16:9 painting on a stage that covers a viewport-wide box, so narrow screens see the middle of the market at a readable pixel size instead of a shrunken whole.
- All art is painted in code by `src/art/` and served as build-time endpoints under `src/pages/art/`. Ground and cliffs are in `terrain.ts`, the far view in `vista.ts`, walls and roofs in `buildings.ts`, the three houses in `town.ts`, trees and plants in `flora.ts`, townsfolk (hand-drawn parts in palette letters) in `folk.ts`, props in `props.ts`, stalls in `stalls.ts`, and the scene in `market.ts`. Objects are layers depth-sorted by the ground line `gy` they stand on, and each casts a shadow sheared from its silhouette. Guild shields and skill icons are derived from ids. Don't commit binary images.
- The scene (640x360) is painted in daylight, then graded. At night `moonlit` tone-maps it: brightness keeps its order on a lifted curve so the square stays readable, colour drains and cools, the sky gets its own night gradient, and then every `Light` relights its surroundings from the daylight copy. `paintMarket(time, frame)` paints four animation frames. `LOOPS` cuts sprite sheets from them (breathing townsfolk, the fountain, the sea), and `Scene.astro` layers those with drifting clouds and gulls, chimney smoke, and at night flickering lantern light and fireflies. It all holds still under `prefers-reduced-motion`. Clicking the sun/moon or any `[data-theme-toggle]` switches the theme (saved in localStorage).
- Preview art while painting: `bun scripts/art-preview.ts <out-dir>` writes upscaled PNGs.
